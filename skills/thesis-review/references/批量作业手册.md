# 批量作业手册

> 面向「一届带8-12 名学生」的规模化场景。
> 核心思想：**把「一个学生写一个脚本」变成「一个脚本扫全班」**。

---

## 一、为什么需要批量

2026 届的实际教训：8 名学生 → 写了 16 个一次性脚本（annotate_peng.py、inspect_wang.py、
verify_wang_tables.py……），每个绑死一个学生。换届全部作废。

**正确做法**：规则与学生解耦。学生只是「参数」，规则是「资产」。

---

## 二、标准作业流水线

```
阶段 0  收论文     学生提交 → IN-1_学生论文/，命名 学号-姓名-题目.docx
   ↓
阶段 1  登记       填 IN-4_学生信息/学生信息.xlsx
   ↓
阶段 2  批量预审   scripts/docx_预审.py IN-1_学生论文/ --json 预审结果.json
   ↓               → 拿到全班 P0/P1/P2 分布，先看「谁是重灾区」
阶段 3  逐个精审   对P0 多的学生做全篇审查，产出审查报告
   ↓
阶段 4  核查答辩意见 填 IN-3_答辩组意见/答辩意见.xlsx → excel_双表同步.py
   ↓
阶段 5  生成批注   scripts/docx_批注.py 论文.docx 批注.json -o 论文-批注版.docx
   ↓
阶段 6  归档材料   交给 Skill「毕设归档材料整改」
```

## 三、阶段 2：批量预审

### 用法

```bash
# 扫全班
python scripts/docx_预审.py IN-1_学生论文/

# 扫单个（深挖）
python scripts/docx_预审.py IN-1_学生论文/202400000001-张三-xxx.docx --all

# 导出 JSON 供后续脚本消费
python scripts/docx_预审.py IN-1_学生论文/ --json 预审结果.json
```

### 输出解读

汇总表按P0 数量排序，**P0 数就是该学生的紧急度**：

| P0 数 | 处置 |
|:---:|------|
| ≥5 | 优先约谈，答辩组必挂 |
| 3-4 | 常规指导，重点盯P0 项 |
| ≤2 | 轻度指导，可自主修改 |

### 预审器的 22 条规则分组

| 组| 规则 | 说明 |
|---|---|---|
| 章节结构 | SEC-001~004 | 缺总结展望、缺空格、编号格式、缺图件 |
| 图表题| CAP-001~003 | 编号重复、格式不一、图文脱节 |
| 代码 | CODE-001~003 | 中文变量名、占位写法、API 文档化|
| 界面截图 | IMG-001 | 实现章节 0 图 |
| 参考文献 | REF-001~003 | 数量、非学术来源、缺页码 |
| 英文摘要 | ABS-001~002 | 中文标点、长度异常 |
| 错别字 | TYPO-001~002 | 常见错字、未完成表述 |
| 数据库 | DB-001~002 | 拼音字段、可空矛盾 |
| 测试 | TEST-001~002 | 数据量不符、缺边界用例 |
| 一致性 | CONS-001 | 实现有、需求无（前后脱节） |

### 已知局限（务必人工复核）

预审器是**正则 + 结构统计**，以下情况会误报/漏报：

| 局限 | 说明 | 处置 |
|---|---|---|
| 代码块识别靠字体启发式 | 字体不是等宽的代码块可能漏检 | 抽查实现章节 |
| CONS-001 依赖「系统实现」「系统设计」字面位置 | 学生改了章节标题就失效 | 人工核对需求分析 |
| DB-001 拼音字段用词表匹配 | 非词表内的拼音漏检 | 看表结构时人工过一眼 |
| TEST-001 靠「共 N 条」字样| 学生换个说法就失效 | 人工核对|
| SEC-004 靠全文关键词 | 正文提一句就算通过 | 看图题而非正文 |

**原则：预审器负责「筛出可疑」，判断由人做。** 不要把 P0 直接发给学生。

## 四、阶段 5：批量批注

### 批注定义文件（JSON）

```json
[
  {
    "find": "3系统分析",
    "level": "P0",
    "comment": "章节编号与标题之间缺少空格，应为「3 系统分析」。全文同类一并检查。"
  },
  {
    "find": "登陆",
    "level": "P2",
    "comment": "「登陆」应为「登录」。请全文检索统一替换。",
    "all": true
  },
  {
    "find": "评价",
    "level": "P1",
    "comment": "评价模块在需求分析中未提及，但这里已实现——补上需求分析。",
    "nth": 3
  }
]
```

### 字段

| 字段 | 必填 | 说明 |
|---|:---:|---|
| `find` | ✓ | 正文搜索锚点，取一段足够唯一的文本 |
| `comment` | ✓ | 批注内容 |
| `level` | | P0/P1/P2，仅用于分类 |
| `all` | | true = 替换全文所有处；缺省 = 仅第一处 |
| `nth` | | 指定第 n 处（从 1 开始） |
| `skip` | | 更精确的定位文本 |

### 先干跑

```bash
python scripts/docx_批注.py 论文.docx 批注.json --dry-run
```

**务必先干跑**。它会报告哪些锚点命中、哪些没命中。锚点写错会导致批注插错位置，
而干跑能在不产生文件的前提下验证。

### 命名锚点的技巧

| 场景 | 差 | 好 |
|---|---|---|
| 章节标题 | `系统实现` | `5系统实现`（含编号更唯一） |
| 错别字 | `登陆` | `登陆`，配 `all:true` |
| 表格标题 | `表4-3` | `表4-3 用户会员信息` |
| 代码段 | `public void` | `public void deleteUser` |

## 五、阶段 4：双表同步

```bash
python scripts/excel_双表同步.py --dry-run          # 先看差异
python scripts/excel_双表同步.py                    # 确认后写入
python scripts/excel_双表同步.py --冲突报告 冲突.csv  # 导出冲突人工核对
```

**冲突时脚本会停下并退出（exit 2），不自动覆盖。** 这是有意设计——
题目冲突往往意味着学生改了题或登记信息过期，必须人工确认。

## 六、时间节点参考

| 时间 | 动作 | 产出 |
|---|---|---|
| 选题后1 周 | 收齐题目，填学生信息表 | `学生信息.xlsx` |
| 开题后 | 收开题报告，一致性核查 | 开题批注 |
| 中期 | 收中期检查，重点看进度与算法 | 中期意见 |
| 定稿后 | **批量预审 → 逐个精审 → 批注版** | 审查报告 + 批注版 |
| 答辩后 | 填答辩意见表 → 双表同步 → 核查修正率 | 核查表 |
| 归档前 | 归档材料整改（另一 Skill） | 整改版全套 |
